# 2026-05-15 Nushell Config Consolidation Design

## Problem
The current Nushell configuration has several issues:
1. **Redundancy**: Both `config.nu` and a `run_onchange` bash script generate the same tool integrations (`starship`, `atuin`, etc.).
2. **Performance**: `config.nu` regenerates these files on every shell start, adding unnecessary latency.
3. **Inconsistency**: User-defined helpers and aliases are in a custom `autoload/` directory that isn't natively supported by Nushell without manual setup, leading to code duplication (like the `is-installed` function).

## Goals
- **Consolidate**: Use Nushell's native `vendor/autoload` mechanism for all configurations.
- **Performance**: Move all heavy initialization to the `run_onchange` script.
- **Cleanliness**: Remove all setup boilerplate from `config.nu`.

## Design

### 1. Directory Structure
Move all configuration fragments to `vendor/autoload`.

**Old Structure:**
```
nushell/
├── config.nu
├── env.nu
└── autoload/
    ├── 00-utils.nu
    ├── 10-aliases.nu
    └── 20-commands.nu
```

**New Structure:**
```
nushell/
├── config.nu
├── env.nu
└── vendor/
    └── autoload/
        ├── 00-utils.nu        # Core helpers
        ├── 10-aliases.nu      # Aliases
        ├── 20-commands.nu     # Custom commands
        ├── starship.nu        # Generated by script
        ├── atuin.nu           # Generated by script
        └── ...                # Other generated integrations
```

### 2. File Changes

#### `private_Library/private_Application Support/nushell/config.nu`
- Remove `is-installed` definition.
- Remove tool initialization logic (`starship`, `atuin`, `zoxide`, `mise`).
- Only keep global settings (like `$env.config.show_banner = false`).

#### `private_Library/private_Application Support/nushell/private_vendor/private_autoload/`
- This directory will now house `00-utils.nu`, `10-aliases.nu`, and `20-commands.nu`.
- Chezmoi will manage these files here.

#### `.chezmoiscripts/darwin/run_onchange_after_nushell-vendor.sh.tmpl`
- Remains the authority for generating tool-specific `.nu` files.
- It already points to `vendor/autoload`, so no path change is needed in the script's output logic.
